- Decided October 12, 2026 (Alex): source limits of 25 MiB (replacing 50 MiB; uploads are usually about 10 MB), 400 pages, 4,000,000 characters of extracted text and 3 minutes per analysis, enforced in the service. Renders are bounded in pixels. pypdf expands the page tree only to four entries per allowed page, so shared /Pages nodes cannot multiply a small file into millions of pages. Time is checked between pages and once more at the end, so one slow page can overshoot the limit by that page before the analysis fails. The model route's candidate scan reads at most 100,000 characters and 50,000 page objects of any kind per page and stops after 2,000 shapes of each kind; each bound is noted on the page when it applies.
- Decided October 12, 2026 (Alex): time spent waiting for PDFium's lock counts toward a source's 3 minutes; the clock is not restarted when its render begins. Measured locally: a 97-page, 3.2 MiB source analyzes in 2 to 3 seconds.

- Model route, BYOK fallback: the gateway cannot refuse a fallback from Alex's key to Vercel's credentials, and the routing metadata shows one only after the call. A fallback that starts mid-run can carry up to `--workers` pages (at most 4) on Vercel's credentials before the run stops. This applies only to models Alex's key reaches: of those offered, `gpt-4.1` and `gpt-5.4-mini`. The other offered models the October 12 probes reached (`gpt-5`, `gpt-5.2`, `gpt-5.4`, `gpt-6.1-sol`, `gpt-6-luna`) ran on Vercel's credentials (`--credential system`), where there is no fallback; the rest were not probed, and the preflight finds out before any page is sent. Decided October 12, 2026 (Alex): accept the fallback and continue, recording it. `--accept-fallback` (BYOK only) lets a call answered on Vercel's credentials pass; the record marks each such call and counts them in `fallback_calls`. Every other route check still applies.

- Open (PR #7 review): the local state API has no identity. That follows the access decision (no custom login, no assumed reviewer identity). Whether the local API needs more, such as a per-launch token, is open. - Decided October 12, 2026 (Alex): an orphan (a create reported or found after its operation was replaced by one that did not fail) is shown as a warning on every operation answer and refuses every create until someone checks the provider and resolves it with a note. Write failures are retried in the store (the R2 store on `feat/hosted-login`; the local store does not retry); what still fails stays as the pre-call operation record, which offers only a status check, and the orphan list holds creates that landed late. Together they are the dead-letter queue, except for an orphan that cannot be written, which is named only in its 503 error. Applied the same way, as an implementation choice rather than a new decision (PR #7 round 6): a create whose outcome is unknown when its operation has been replaced is treated like one reported or found. Decided October 12, 2026 (Alex): the earlier orphan format (one file per operation), written only by this draft branch, gets no migration.
