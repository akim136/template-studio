Three intentional Vercel choices

PrimitiveWhy it fitsTrade-off
FunctionsHosts Python 3.13/FastAPI, document parsing and per-page request APIs without a dedicated server.Time-bounded work. Browser-driven drafting is resumable while a Studio tab is open, but not a durable server queue.
AI GatewayRoutes Stage A/B calls to OpenAI using Vercel OIDC; the server checks the route and enforces a $20 spend cap.Model quality depends on the app's evidence, prompts and visual self-check. The model is fixed in code (gpt-5.4-mini), with no model selector.
Preview DeploymentsBranch builds support repeatable UI/code review before merging to production.Previews are not behind Vercel Authentication and share production's sign-in app and synthetic-only R2 bucket. Separate preview data is still needed.

Access: Vercel Authentication is off. Sign in with Vercel (OAuth/PKCE) gives identity, the verified email on each review and approval, not authorization: any Vercel account can sign in, so the hosted studio stores synthetic documents only. Fluid Compute: enabled, with workload benefit not verified.

Drafting continues while a Studio page remains open; there is no server-side queue, and a deploy that changes the model route or prompts stops a running draft. No signing-provider template is created.

Canary

One Homebase teammate and one supported document family. Measure corrections, time and failures.

Cutover

Use Studio as default only after supervised acceptance. Build and approve a real signing integration separately.

Rollback

Stop new Studio work, preserve R2 revisions and fall back to the existing Claude-based process. Reconcile any future external create separately.

06

What success looks like

Technical quality

Complete supported-page coverage; correct field type, signer and placement; reliable conditional saves and revision-bound approval; logged latency, failures and AI spend.

Business outcome

A teammate finishes without founder intervention, with less manual placement, fewer restarts, and lower cost per accepted draft at equal reviewed quality.

Canary gate: no critical missing signature, signer mix-up or approval bypass in the agreed cases; successful unaided reviewer workflow and safe interrupted-job recovery.

These are proposed outcomes, not measured savings or established accuracy. Compare initial AI draft, self-checked draft and human-final revision separately.

DELIVERY / RISK / EVIDENCE
07

Limitations & customer considerations

Supported PDF boundaries

25 MiB, 400 pages, 4 million characters and a 3-minute limit. Rotated pages are not sent to the model and must be confirmed by hand.

AI quality remains provisional

On the development documents, both trial models still miss required signing fields or signers. Human review stays required.

Hosted-only drafting

Up to four page requests run concurrently while Studio is open. No local drafting or independent server queue.

R2 state and privacy

Conditional writes protect revisions; verify conflicts, origin rules, model-provider exposure and access scope for pilot use.

Reviewer access

Sign in with Vercel identifies each reviewer, but any Vercel account can sign in: there is no allowlist. Storage is synthetic-only for that reason.

Simulated creation only

Each create is recorded, then read back from the studio's storage. No HelloSign/Dropbox Sign API operation occurs.
